## Hallazgos de esta corrida

### LIVE-REF-210343-01 — typo de producto deriva a otro modelo

Estado: **FIXED-CODE**

Evidencia observada:

`armro x13` → fallback de alternativa → `Armor X12 Pro` → `y stk?`/imagen siguieron X12 Pro → `ya el 22 quiero` terminó intentando reserva sobre X12 Pro.

Causa:

- resolución de typo no tenía autoridad suficiente frente al producto viejo;
- un follow-up ambiguo podía aceptar un target distinto propuesto por planner;
- una selección corta explícita podía quedar dominada por el target viejo.

Cambios aplicados:

1. typo recovery contra catálogo SQL canónico, fail-closed si es ambiguo;
2. follow-up factual sin producto nuevo conserva el producto activo canónico;
3. compra explícita puede elegir el único candidato SQL nuevo distinto del producto activo;
4. no se hardcodea Armor 22/X13/X12: la regla usa identidad canónica SQL.

Próximo Live debe comprobar:

- `armro x13` → X13;
- `y stk?` → sigue X13;
- `foto` → sigue X13;
- `el 22 ...` → consulta Armor 22 sin destruir contexto;
- `ya el 22 quiero` → selecciona/reserva Armor 22, nunca el producto anterior.

### LIVE-FAB-210343-01 — beneficio inferido sin evidencia

Estado: **FIXED-CODE**, pendiente Live.

FAB permanece obligatorio pero seguro:

`Feature verificable → Advantage verificable → Benefit contextual seguro`.

No se permite inferir solo desde un número:

- 6600 mAh → `dura todo el día`;
- RAM → `sin lags`;
- más constelaciones → `GPS más estable`;
- más MP → `mejor video` o `mucho mejor en baja luz`;
- almacenamiento → cantidad concreta de fotos sin supuesto verificable.

Writer prompt + guard general bloquean estas familias cuando no aparecen sustentadas en evidencia.
